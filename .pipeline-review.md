## Round 2 (QA gate rework)

Reviewer: opus-4.8 code-reviewer subagent, 2026-07-09. Scope: incremental HEAD (git show HEAD) over the branch -- synchronous double-click disarm in ApprovalCard.tsx, autoFocus, no-op save hygiene in lib/approvals.ts, cleanup script line-ending handling.

Correctness: PASS
- Synchronous disarm is race-free. setArmed(false) + setEditing(next) share one discrete click handler; React 19 batches and flushes the commit before the next click event dispatches, so swapped-in footer buttons MOUNT with disabled={!armed}. No post-paint effect gap.
- The [armed] effect never disarms on mount: armed initializes true and the `if (armed) return` guard bails on the initial run; the 400ms re-arm only schedules after an explicit toggle set armed false.
- pendingItemOrThrow throws "...: no pending_approval item with id ..."; isAlreadyDecided matches the "no pending_approval item" substring, so both a zero-row SELECT and a zero-row guarded UPDATE surface as the inline already-decided message, not a thrown 500.
- SELECT-then-UPDATE window is benign: the pre-read only feeds the sameDraft no-op check; the guarded WHERE status = 'pending_approval' UPDATE stays authoritative, so a decision landing mid-window fails loudly rather than writing.
- No-op Save & approve downgrades edits to undefined and takes the edited===undefined UPDATE branch, which reads edited back from payload.draft_edited via coalesce(...,false): a prior genuine Save edits still records edited:true, an untouched draft records edited:false and captures no original_draft.
- Cleanup script: IS NOT DISTINCT FROM over replace(..., E'\r\n', E'\n') is NULL-safe and normalizes both sides; restore uses jsonb -> preserving stored types, then strips original_draft and draft_edited; app reads missing draft_edited as false; genuine (normalized-unequal) edits are not matched.

Efficacy: PASS
- Mount-disabled closes the double-click gap for every button-swapping transition: edit-toggle, cancel-edit, and the post-save editor close. Live tests (6-position 120ms-gap double clicks, real double/triple clicks) all hit disabled buttons.
- Residual same-button rapid submits (Approve/Reject/Save edits, which do not change position) are covered by the guarded single-statement UPDATE and jsonb idempotency, so no rapid click sequence yields a duplicate or spurious write. No-op save left payload md5 unchanged; genuine edit persisted LF-only.

Minor (non-blocking, <80 confidence): re-toggling within the 400ms window (cancel then edit) does not restart the timer because setArmed(false) on an already-false value bails out, so the immunity window can end slightly early; harmless given the DB guard. Double-clicking a non-swapping submit (e.g. Approve) can briefly flash the already-decided alert before revalidation unmounts the card; cosmetic, pre-existing.

SUMMARY: PASS. Double-click immunity, no-op save hygiene, and the cleanup script are correct and effective; ship it.
